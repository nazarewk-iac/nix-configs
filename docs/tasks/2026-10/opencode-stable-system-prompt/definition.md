# Stable OpenCode system prompt (no date injection)

> ✅ **Done** — see the solution in [done.md](done.md).

## Context

OpenCode builds the system prompt with an `<env>` block that ends in
`Today's date: <date>` (`packages/opencode/src/session/system.ts:81`, version
1.18.29). The date changes at midnight, so the prompt prefix changes and a
server-side prompt cache cannot reuse it.

On the hybrid Qwen model on brys this is expensive: a divergence inside the
system prompt is before the first context checkpoint, so llama.cpp forces a full
re-process of the whole conversation (see
[../llm-warm-start-session/hybrid-reuse.research.md](../llm-warm-start-session/hybrid-reuse.research.md)).
A ~258K-token conversation costs ~2.6 h before the first token.

## Goal

Replace the date line with a stable line that points at a small `current-date`
skill, so the prompt prefix is byte-stable for the life of a conversation and
the model still knows how to obtain the date on demand.

## Findings

- OpenCode 1.18.29 has **no config option and no environment variable** to
  disable the date injection. See [research.md](research.md).
- The only supported hook is the plugin `experimental.chat.system.transform`,
  which receives the system prompt as a mutable `string[]`. The date is one line
  in that array.
- OpenCode skills live at `.opencode/skills/<name>/SKILL.md`. The system prompt
  gets only the skill's **name and description** (stable, sorted); the body
  loads on demand through the `skill` tool.
- The `kdn.opencode` aspect already writes files into `.opencode/`, and the
  `kdn.llm-client` aspect already writes a plugin there, so the mechanism
  exists.

## Approach

1. Write a plugin into `.opencode/plugins/` (generated by the aspect) that
   replaces the `Today's date:` line with a stable line that names the
   `current-date` skill.
2. Track the `current-date` skill as **repo content** at
   `.opencode/skills/current-date/SKILL.md`. It tells the model to run `date`
   when it needs the date. It is not generated, so git tracks it.
3. Own the plugin in the `kdn.opencode` aspect
   (`modules/den/aspects/opencode.nix`), because the date injection is general to
   OpenCode, not specific to the LAN providers. Mirror it in the slot
   (`modules/slots/opencode/default.nix`).
4. Un-ignore `.opencode/skills/*/SKILL.md` in `.gitignore`, so the skill is
   tracked while the rest of `.opencode/` (node_modules, the generated plugin
   symlinks, package files) stays ignored.
5. Guard the hook so a missing or renamed hook never breaks a request.

## Acceptance criteria

- The generated `.opencode/plugins/kdn-opencode-stable-prompt.ts` exists.
- `.opencode/skills/current-date/SKILL.md` is a tracked real file.
- With the plugin loaded, the system prompt has no injected date and names the
  `current-date` skill.
- Two requests on different days produce an identical system prompt.

## Open questions

- The hook is `experimental` and v1-only. OpenCode v2 replaces it with
  `ctx.session.hook("context", ...)`. The plugin must be revisited on a v2
  upgrade.
- The date is not injected, so the model must run `date` to answer a date
  question. The alternative is to freeze the first-seen date per session.
- Other parts of the prompt still move: the instruction content is re-read every
  request, so editing `AGENTS.md` mid-session forces a re-prefill. See
  [prompt-volatility.research.md](prompt-volatility.research.md).
