## The 12 questions, per candidate — where they are answered

1. **Maintenance** — master table column 1 + per-candidate detail in the reports
   (rosec §1, keepassxc §1, gopass §1, small-implementations §1/§2/§3, oo7 §1).
2. **Popularity / reputation / security** — column 2; security records: rosec (no
   advisories, no audit), keepassxc (6 GHSAs + 3 disputed CVEs, table in the report),
   gopass (3 medium store-escape advisories in 2026, all fixed, audit remediation in
   1.17.0), oo7 (none published), bitw (abandoned).
3. **API completeness** — column 3; exact interface lists in the reports (rosec §4,
   keepassxc §3, gopass §4, small-implementations §1–3, oo7 §"D-Bus names").
4. **Correctness** — column 3 + the interop appendix of
   `small-implementations.md`: **DH session interop is not a differentiator** — all
   five implementations (the three small ones, libsecret, SecretStorage) derive the
   same HKDF key (zero-salt HKDF-SHA256), so the old hypothesis "mdellweg's DH breaks
   libsecret clients" is **wrong**; mdellweg's breakage is UTF-8, alias, gpg-id and
   activation (§below).
5. **Extensibility** — rosec: clean `Provider` trait in `rosec-core` + WASM guest
   contract (an age/sops file-tree provider = low-to-moderate effort, no D-Bus/agent
   code touched); gopass: the store is gopass itself (age backend), no seam below it,
   but the backend choice is the seam; grimsteel: `SecretStore` trait (the best seam
   of the three small ones); yousefvand/mdellweg: no seam; keepassxc: KDBX is closed
   (PR #8591 separates the bridge from the GUI, milestone 2.9.0 — track, do not fork).
6. **Headless** — [research.headless.md](research.headless.md).
7. **Packaging** — table above + the nixpkgs survey in `oo7-bitw-nixpkgs.md` §3
   (units and D-Bus activation files per package).
8. **Storage format** — [research.storage.md](research.storage.md).
9. **Sync** — [research.storage.md](research.storage.md).

## Known fault case: why `mdellweg/pass_secret_service` broke tools (code-confirmed)

The previous implementation in this environment. Diagnosis from its source (full
quotes in `small-implementations.md` §3):

1. **Hardwired GPG, root `.gpg-id` required.** Storage is `pypass`, which reads the
   whole `.gpg-id` file as one string and refuses to start without a GPG store. A
   pass store that is not GPG-recipient-shaped (or age/sops at all) cannot be used.
2. **Multi-recipient `.gpg-id` → every write fails** (issue #34, reported by
   `nazarewk`). The multi-line `.gpg-id` becomes one invalid gpg recipient:
   "Invalid user ID" on every `CreateItem`/`SetSecret`.
3. **Binary secrets crash** (issue #39, still open; NixOS reports incl. 1Password,
   Fractal, Nextcloud). Every secret is forced through
   `password.encode("utf8")` / `.decode("utf8")` → `UnicodeDecodeError`.
4. **`CreateCollection` with a taken alias re-points the alias** to a brand-new
   collection, orphaning the old items (issue #36, `aws-vault`, same reporter) —
   the spec says the existing collection must be reused.
5. **`Unlock` is a no-op flag; `GetSecret` ignores locked state; `Locked` is
   hardcoded `false`** (issue #32).
6. **Shipped D-Bus activation is broken**: the `[D-BUS Service]` file has
   `Exec=/bin/false`; the systemd fallback unit is `Type=simple` (no `Type=dbus`), so
   nothing waits for the bus name.
7. Minor: `ReadAlias("default")` returns the collection UUID path; `Created`/
   `Modified` hardcoded 0; no Prompt objects (module renamed `prompt.py_tilt`);
   plaintext JSON metadata on disk; Py3.14 start crash until 2026-07-15.

Items 2–4 are the plausible cause of "it broke several tools": writers died (2),
binary secrets died (3), and alias-scoped readers saw orphaned collections (4). The
DH-session hypothesis from the task definition is **refuted** by the interop
measurement (same HKDF key in every implementation).
